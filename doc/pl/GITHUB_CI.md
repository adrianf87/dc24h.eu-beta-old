# CI w GitHub Actions

Testy ncdc z konfliktem interfejsów rezerwują porty na obu adresach loopback i zachowują drugi nasłuch do gotowości klienta. Wyłącznie kolizja EADDRINUSE przy przydziale wybiera nową parę w ograniczonej pętli; sam test nie jest ponawiany. `integration.ncdc_ports` sprawdza deterministyczne kolizje TCP/UDP i sprzątanie.

Workflow `Check status` z `.github/workflows/build.yml` uruchamia się wyłącznie na własnym runnerze Debian 13 `server-759505093`. Macierz Ubuntu **22.04**, **24.04** i **26.04** korzysta z oficjalnych kontenerów Docker, a nie maszyn GitHub-hosted. Każdy kontener otrzymuje osiem logicznych wątków CPU (`--cpuset-cpus=0-7`) i limit 8 GiB RAM bez limitu czasu CPU. Zależności testowe są instalowane w kontenerach, nie na hoście. Szczegóły: [instrukcja runnera](../../self-hosted-runner/README.md).

Etap I beta-0.3.3 usunął historyczne założenie o dokładnie czterech logicznych CPU; zadania używają teraz ośmiu wątków dostępnych wewnątrz kontenera. Etap II beta-0.3.7 dodaje testy TOTP, anty-replay i sesji MFA do testów Node WebAdmin. Etap III beta-0.3.10 dodaje testy szyfrów i nagłówków HTTPS, ograniczenia izolacji i testy prywatnego pilotażu. Etap IV beta-0.3.12 dodaje testy obciążenia/awarii, audytu i wydania. Push, PR do `main` i ręczne wywołanie pozostają, ale wykonanie testów jest ograniczone do użytkownika `adrianf87`, a PR z forków są blokowane. Uprawnienia workflow to tylko odczyt; poświadczenia checkout nie są zachowywane. Jeden runner wykonuje zadania po kolei.

Na każdym z trzech obrazów Docker uruchamiane są C++ Debug, C++ Release i WebAdmin. W kontenerze dostępne jest osiem wątków, lecz liczba równoległych kompilacji, testów CTest i przeglądarek jest mniejsza, aby zmieścić się w 8 GiB RAM. Krok C++ wykonuje `dependencies.audit` i `beta.baseline`. Zobacz [Zależności](DEPENDENCIES.md) oraz [Linię beta](BETA.md). WebAdmin po `npm ci` audytuje zależności, buduje TypeScript i wykonuje testy Node/Chromium oraz integrację C++ na Node.js 22. Dwie dodatkowe kompilacje Ubuntu 24.04 w Dockerze uruchamiają ASan i UBSan; ich wyniki warunkują wymagany check `CI (C++ and WebAdmin)`. Nie są to testy ThreadSanitizer ani fuzzing sterowany pokryciem.

Jedna grupa współbieżności na workflow i ref, `dc24h-github-` plus nazwa workflow i ref, ma `cancel-in-progress: false`. Zadanie C++ ma limit 120 minut, a WebAdmin 60 minut. Testy Stage IV Ubuntu również działają w Dockerze na tym samym runnerze. Osobna macierz pięciu dystrybucji pozostaje domyślnie wyłączona i wymaga ręcznego zatwierdzenia.
