# GitHub Actions CI

The ncdc cross-interface fixtures reserve ports on both loopback addresses, retaining the conflicting listener until the client is ready. Allocation-only EADDRINUSE collisions choose a fresh pair with bounded retries; test failures are never retried. `integration.ncdc_ports` covers deterministic TCP/UDP collisions and cleanup.

The `Check status` workflow in `.github/workflows/build.yml` runs exclusively on the self-hosted Linux x64 runner `server-747585786`. Its Ubuntu **22.04**, **24.04** and **26.04** matrix entries select official Docker job containers, not GitHub-hosted VMs. Each container uses eight logical CPU threads via Docker `--cpuset-cpus=0-7`, a memory ceiling of 8 GiB and no CPU-time quota. The new host's Linux distribution, Docker permissions and available hardware must be checked; OS-native test dependencies are installed only in disposable containers. See the [self-hosted runner operating guide](../../self-hosted-runner/README.md).

Stage I beta-0.3.3 removed the historical assumption of exactly four logical CPUs; containers now expose eight CPU threads but resource-heavy compiles, CTest and browser tests use bounded worker counts to stay inside 8 GiB. Stage II beta-0.3.7 adds TOTP verifier/replay and MFA login tests to the WebAdmin Node suite. Stage III beta-0.3.10 adds HTTPS cipher/header integration checks, optional sandbox constraints and fixed-route private pilot preflight tests. Stage IV beta-0.3.12 adds bounded stress/failure tests, validated nonsecret audit records and a CTest release gate. The workflow retains its push, pull-request-to-`main` and manual events, but **test execution is gated to actor `adrianf87`; fork PR heads are rejected**. The workflow has read-only repository permissions and disables persisted checkout credentials. Use the workflow file for the authoritative branch list. The single self-hosted runner schedules queued jobs one at a time.

Three job types run on each of those three images: C++ Debug, C++ Release and WebAdmin. The C++ step runs `dependencies.audit` to check shared libraries, the locked WebAdmin package catalog and registered security tests; it also runs `beta.baseline`. See [Dependencies](DEPENDENCIES.md) and [Beta baseline](BETA.md). The WebAdmin job checks high-severity production npm advisories after `npm ci`, then builds, typechecks, runs Node/Chromium and the real C++ API integration on Node.js 22. Two additional Ubuntu 24.04 Docker jobs run the instrumented security test subset with ASan and UBSan; their results gate the existing named required CI check. These are not ThreadSanitizer or coverage-guided fuzzing runs. Non-TLS bytes on a TLS port may end as EOF or one fatal alert record; the server still does not call SSL_shutdown().

Concurrency uses one group per workflow and ref, `dc24h-github-` plus the workflow name and ref, with `cancel-in-progress: false`. The C++ job has a 120-minute timeout and the WebAdmin job has a 60-minute timeout. The required check name is still `CI (C++ and WebAdmin)`. The separate Stage IV Ubuntu matrix also uses this self-hosted runner and Docker. The five-distribution Debian/Ubuntu suite remains a separate **manual-only, default-off** workflow. Check each run under [GitHub Actions](https://github.com/adrianf87/dc24h.eu-high-starter/actions/workflows/build.yml) for actual results. CI completion is not awaited.

Push triggers CI; remote completion is not awaited.
